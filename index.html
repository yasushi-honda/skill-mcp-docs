Skill Distribution / Remote MCP Server

skill-mcp

Claude・Claude Code・Cursor などに「本人専用の接続URLを1本渡すだけ」で、 サーバー側に一元管理したスキル（プロンプト）を使わせるための、 Cloudflare Workers 上で動くリモート MCP サーバーです。

https://skill-mcp.spring-band-712b.workers.dev/mcp?token=skm_live_K0LbUAogdTv8bwAH3I94Tzm2vw3WYKR1yRMcQ87a5Ow

概要

利用者ごとに専用トークン付きのURLを1本発行するだけで、管理者が用意したスキル （アイデア壁打ち・議事録要約・コードレビュー観点 など）をそのまま使わせられます。 社内メンバーへの展開はもちろん、社外のクライアントへの配布にも使える汎用的な仕組みです。 スキル本文はサーバー側で一元管理しているため、内容を更新すれば次の呼び出しから全員に反映されます。

配布
URLを1本渡すだけ。個別のセットアップ作業は不要。
制御
トークンごとに使えるスキルを制限。失効も即時反映。
記録
誰が・いつ・どのスキルを使ったかをログに記録。

全体の流れ

管理者がゼロから使える状態にするまでは、次の4ステップです。各ステップから詳細セクションへ移動できます。

1 構築する Cloudflareにデプロイ 2 スキルを登録する 配りたいプロンプトを追加 3 配布する トークンを発行してURLを渡す 4 運用する 追加・失効・利用状況の確認

アーキテクチャ

Cloudflare Workers 1つの上で、利用者向けの MCP エンドポイント（/mcp）と 管理者向けの管理API（/admin/*）を提供しています。状態は D1（SQLite互換）に 持たせ、Durable Objects のようなセッション管理は使わないステートレス設計です。

未許可のスキルは MCP ツールとして登録されないため、 tools/list にすら現れません。実行時の権限チェック漏れが構造的に起きない設計です。

1

構築する

ここからは実際に手を動かす4ステップの本編です。まずはシステム自体をCloudflareにデプロイします。 実装はAIコーディングツール（Claude Code など）に下の要件をそのまま渡せば、ほぼ自動で組み上がります。

必要なもの

  • Cloudflareアカウント（無料。dash.cloudflare.com/sign-up）
  • GitHubアカウント
  • Node.js 20以上
  • Claude Code などのAIコーディングツール（必須ではないが、実装を任せる前提の手順）

Claude Codeに渡すプロンプト

新規プロジェクトのディレクトリで、まずこれを渡して設計方針を出させてから実装に進めるのがおすすめです。

Claude Code に貼り付ける（構築プロンプト） 
Cloudflare Workers + D1 + MCP（Model Context Protocol, Streamable HTTP）で、
「プロンプト（スキル）配布用のリモートMCPサーバー」を実装してください。

要件:
- 複数のプロンプトをサーバー側で一元管理し、内容を更新したら次回呼び出しから
  全利用者に反映されるようにする
- 利用者ごとに専用トークンを発行し、そのトークンで使えるプロンプトを制限できるようにする
- トークンの発行・一覧・失効を行う管理APIを用意する。管理用の認証情報は
  利用者用トークンとは別名前空間で保護する
- 誰が・いつ・どのプロンプトを呼んだかをログに記録する
- MCPクライアント（Claude Code, Cursor, Claude Desktop など）からStreamable HTTPで
  接続できるようにする。トークンはクエリパラメータとAuthorizationヘッダーの
  両方に対応させる
- 未許可のプロンプトはMCPツールとして登録しない設計にする（tools/listにも出ないようにする）

技術スタック: Cloudflare Workers, D1, Hono, @modelcontextprotocol/server（v2, Streamable HTTP）, TypeScript

まず設計方針とファイル構成を提示して、確認を取ってから実装してください。

デプロイ手順

  1. 上のプロンプトをClaude Codeに渡し、コード一式を実装してもらう
  2. Cloudflareにログイン 
    npx wrangler login
    ブラウザが開くので認証を承認する
  3. D1データベースを作成 
    npx wrangler d1 create <データベース名>
    出力される database_id を wrangler.jsonc（または .toml）に反映する
  4. マイグレーションを本番に適用 
    npx wrangler d1 migrations apply <データベース名> --remote
  5. 管理用トークンをシークレットとして登録 
    npx wrangler secret put ADMIN_TOKEN
  6. デプロイ 
    npx wrangler deploy
    初回は workers.dev サブドメインの登録が必要（ダッシュボードの Workers & Pages 画面、または対象Workerの Domains タブから有効化できる）。 成功すると https://skill-mcp.xxxxx.workers.dev のようなURLが表示される。 これが以降の説明で <worker-url> と書いている部分の実体（このページの 今すぐ試すで使っているURLも、同じ仕組みで得られたもの）。

ここまでで管理者用の接続URL（/mcp）と管理API（/admin/*）が動く状態になる。 ただしこの時点ではスキルはまだ1つも登録されていない。

次のステップは、別の場所やCloudflareの管理画面ではなく、今Claude Codeが作ったこの同じプロジェクトの中で行う。 スキルはデータベースや別サービスに「登録」するものではなく、プロジェクトのソースコードにファイルとして 書き加え、コードごと再デプロイすることで反映される仕組みになっている。

2

スキルを登録する

ここでの作業場所は先ほど構築した同じプロジェクトのディレクトリ。 Cloudflareの管理画面や別のサービスに切り替える必要はない。スキルの実体はソースコード内の ファイルであり、コードごと再デプロイすることで初めて反映される （D1のような外部ストレージではなく、Workers自体にバンドルされる。アーキテクチャ図を参照）。

「1スキル = 本文ファイル1つ + 一覧への登録1件」という構成にしておくと管理しやすい。 本文はプレーンテキスト（Markdownなど）、一覧はそれを読み込んで id / title / description / 本文 を紐づける設定ファイルにする。

  1. スキルの本文（プロンプト）をテキストファイルとして書く（例: skills/meeting-notes.md）
  2. 一覧の設定ファイルに、そのスキルの情報を1件追加する（下記イメージ参照）
  3. description には、利用者がどう話しかけそうかを日本語で具体的に書く。 ここがクライアント側AIのツール選択精度を左右する （例:「この議事録まとめて」「ネクストアクション出して」といった発話例を含める）
  4. デプロイし直す（npx wrangler deploy）。次回の呼び出しから全利用者に反映される
{
  id: "meeting-notes",
  title: "議事録要約",
  description:
    "会議のメモや録音の書き起こしから要点整理をしたいときに使う。" +
    "「この議事録まとめて」「ネクストアクション出して」といった相談で呼び出す。",
  body: (本文ファイルの中身),
}

実装をClaude Codeなどに任せている場合は、コマンドを自分で書かず次のように頼むだけでよい:

Claude Code に貼り付ける（スキル追加） 
新しいスキルを1つ追加してください。

id: meeting-notes
タイトル: 議事録要約
発動条件（description）: 会議のメモや録音の書き起こしから要点整理をしたいときに使うスキル。「この議事録まとめて」
「ネクストアクション出して」といった相談で呼び出されるようにする。
本文: 以下のプロンプトをそのまま使う

---
（ここに実際のプロンプト本文を貼る）
---

追加したらデプロイまで行ってください。

追加しただけでは全員が使えるわけではない。未許可のスキルはツールとして登録されないため、 次のステップでトークン発行時に許可スキルとして指定した利用者だけが実際に使える。

3

配布する

管理者は管理APIでトークンを発行し、そのトークン付きの接続URLを利用者に渡す。 利用者は使っているクライアントに応じて、そのURLを登録するだけでよい。 Claude Code・Cursor はそれ自体がエージェントとして動くツールなので、コマンドやJSONを 自分で書かなくても、下の「自然文で頼む」をコピペしてチャットに貼るだけで設定してくれる。

トークンを発行する

まず管理者が、構築するでデプロイしたWorker（<worker-url>）に対して管理APIを呼び、 利用者用のトークンを1つ発行する。エンドポイントの形は実装によって多少異なるが、典型的には次のようになる: 

curl -X POST https://<worker-url>/admin/tokens \
  -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -d '{"allowed_skills": ["meeting-notes"]}'

# レスポンス例
# { "token": "skm_live_xxxxxxxxxxxx", ... }

ADMIN_TOKEN は構築するのデプロイ手順で wrangler secret put により Worker自身に設定した、管理者だけが知っている値。レスポンスに含まれる token の値が、 以降このページで <あなたのトークン> と書いている部分の実体になる。 <worker-url> と組み合わせた https://<worker-url>/mcp?token=<あなたのトークン> という1本のURLを、 これから配布する利用者に渡す。

Claude Code

コマンドで直接登録する場合:

claude mcp add --transport http skill-mcp "https://<worker-url>/mcp" \
  --header "Authorization: Bearer <あなたのトークン>"

登録後 /mcp コマンドで connected になっていれば成功です。

自然文で頼む場合、Claude Codeのチャットにそのまま貼り付けてください:

Claude Code に貼り付ける 
MCPサーバーを追加してください。名前はskill-mcp、接続方式はHTTP、URLは https://<worker-url>/mcp、認証は Authorization ヘッダーに Bearer <あなたのトークン> を設定してください。

Cursor

~/.cursor/mcp.json（全プロジェクト共通）または .cursor/mcp.json（プロジェクト単位）に直接追記する場合:

{
  "mcpServers": {
    "skill-mcp": {
      "url": "https://<worker-url>/mcp",
      "headers": {
        "Authorization": "Bearer <あなたのトークン>"
      }
    }
  }
}

自然文で頼む場合、Cursorのチャットにそのまま貼り付けてください:

Cursor に貼り付ける 
~/.cursor/mcp.json にリモートMCPサーバーを追加してください。名前はskill-mcp、URLは https://<worker-url>/mcp、Authorizationヘッダーに Bearer <あなたのトークン> を設定してください。

Claude（claude.ai / Claude Desktop）

「カスタムコネクタ」機能（Settings もしくは Customize → Connectors → Add custom connector）で登録します。 ヘッダー認証は現状ベータのため、接続URLにトークンを直接含めた形をそのまま貼るのが確実です。 

https://<worker-url>/mcp?token=<あなたのトークン>

接続後の流れ

登録が終われば、あとは普通に話しかけるだけです。

「このアイデアどう思う？壁打ちして」

と言えば、対応するスキルのツールが自動的に選ばれ、スキル本文が適用されます。 何が使えるか分からないときは「使えるスキル一覧を見せて」と言えば一覧が返ります。

裏側では次のようなやり取りが行われています。

sequenceDiagram
  actor U as 利用者
  participant C as クライアント
  participant W as Worker (/mcp)
  participant D as D1

  U->>C: 「壁打ちして」
  C->>W: tools/list（Bearer token）
  W->>D: トークン検証
  D-->>W: 有効・許可スキル一覧
  W-->>C: 許可されたツールのみ返す
  C->>W: tools/call skill_idea_sparring
  W-->>C: スキル本文（プロンプト）
  W->>D: 利用ログを非同期で記録
  C-->>U: スキルに沿って壁打ち開始
4

運用する

トークンの発行・一覧・失効は管理API経由でコマンド一つで行える。利用状況もいつでも確認できる。 問題があるトークンは即座に失効させれば、以後そのトークンでの接続は全て拒否される。 

stateDiagram-v2
  [*] --> active: 管理者が発行
  active --> revoked: 管理者が失効
  active --> expired: 有効期限切れ
  revoked --> [*]
  expired --> [*]

配りたいスキルが増えた・内容を直したくなった場合は、いつでも スキルを登録するの手順に戻って追加・更新すればよい。 デプロイし直すだけで、次回の呼び出しから全利用者に反映される。

スキルを削除する

  1. スキルを登録するで追加した本文ファイルと、一覧の設定ファイルからそのスキルのエントリを削除する
  2. デプロイし直す（npx wrangler deploy）

実装をClaude Codeなどに任せている場合は、「スキルを削除して」だけではどのスキルかが伝わらない。 削除したいスキルのidまたはタイトルを添えて、次のように頼むとよい:

Claude Code に貼り付ける（スキル削除） 
スキルを1つ削除してください。

対象: meeting-notes（議事録要約）

本文ファイルと一覧の設定ファイルの両方からこのスキルのエントリを削除し、
デプロイまで行ってください。

削除したスキルを許可スキルに含むトークンがあってもエラーにはならず、該当ツールが利用者側の一覧 （tools/list）から消えるだけ。過去の利用ログはそのまま残る。

セキュリティ設計

項目設計
トークン 256bit乱数。サーバーには SHA-256 ハッシュのみ保存し、平文は保存しない。発行時に一度だけ表示される。
権限制御 許可されていないスキルはツールとして登録されないため、一覧にも実行にも現れない。
失効 管理APIから即時失効可能。以後そのトークンでの接続は全て拒否される。
管理用認証情報 利用者用トークンとは別名前空間（ADMIN_TOKEN）で保護。値自体をどこにも保存せず、 パスフレーズから毎回同じ値を計算で導出する運用も可能。
監査 誰が・いつ・どのスキルを呼んだかを利用ログに記録。異常があれば即座に該当トークンを失効できる。

FAQ

運用でよく聞かれる質問をまとめました。質問をクリックすると回答が開きます。

トークンが失効(revoked)・期限切れになっていないか、URLやヘッダーのトークンを打ち間違えていないかを管理APIの一覧で確認する。

そのトークンの許可スキル（allowed_skills）に対象スキルのidが含まれているか確認する。 含まれていなければ、許可範囲を含めてトークンを発行し直す必要がある。

ステートレス設計のため、デプロイが完了すれば次のリクエストから即反映される。反映されない場合は デプロイ自体が失敗していないか、クライアント側がツール一覧をキャッシュしていないか （MCPクライアントを再接続すると解消することが多い）を確認する。

その利用者に発行したトークンだけを管理APIで失効する。他の利用者のトークンには影響しない。

利用ログ（usage_logs）に、トークン単位・スキル単位で呼び出し履歴が記録されている。管理APIから確認できる。

乱数で発行して保管する運用のほか、パスフレーズから毎回同じ値を計算で導出する運用にもできる。 後者であれば、同じパスフレーズを入力し直すだけで再現でき、忘れた場合も新しいパスフレーズで再導出して 差し替えればよい（発行済みの利用者用トークンには影響しない）。

変わらない。トークンとスキルは別管理（トークンは許可スキルidの一覧を持つだけ）のため、 スキルの追加・削除・本文更新をしても配布済みのURL・トークンはそのまま使い続けられる。

できる。スキルを登録するの手順で本文ファイルと設定ファイルのエントリを作り直し、 再デプロイすればよい。削除前と同じidで再登録した場合、そのidを許可スキルに 含んでいた既存トークンは、トークンを発行し直さなくても再デプロイ後に自動で再び使えるようになる （許可判定は常に現在のスキル一覧との突き合わせで行われるため）。別のidで登録し直す場合は、 ["*"]許可のトークン以外は改めて許可スキルを指定してトークンを発行し直す必要がある。
