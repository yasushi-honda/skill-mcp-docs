Skill Distribution / Remote MCP Server

skill-mcp

Claude・Claude Code・Cursor などに「本人専用の接続URLを1本渡すだけ」で、 サーバー側に一元管理したスキル（プロンプト）を使わせるための、 Cloudflare Workers 上で動くリモート MCP サーバーです。

概要 アーキテクチャ 利用の流れ クライアント接続手順 セキュリティ設計 運用

概要

受講生・利用者ごとに専用トークン付きのURLを1本発行するだけで、管理者が用意したスキル （マーケティング壁打ち・入口設計・メルマガ設計 など）をそのまま使わせられます。 スキル本文はサーバー側で一元管理しているため、内容を更新すれば次の呼び出しから全員に反映されます。

配布
URLを1本渡すだけ。個別のセットアップ作業は不要。
制御
トークンごとに使えるスキルを制限。失効も即時反映。
記録
誰が・いつ・どのスキルを使ったかをログに記録。

アーキテクチャ

Cloudflare Workers 1つの上で、利用者向けの MCP エンドポイント（/mcp）と 管理者向けの管理API（/admin/*）を提供しています。状態は D1（SQLite互換）に 持たせ、Durable Objects のようなセッション管理は使わないステートレス設計です。 

flowchart LR

    CC["Claude Code"]
    CD["Claude / Claude Desktop"]
    CU["Cursor"]
  end

  subgraph worker["Cloudflare Workers"]
    MCP["/mcp（Streamable HTTP）"]

  D1[("D1\ntokens / usage_logs")]
  SKILLS[["src/skills/*.md\n（スキル本文）"]]
  OPERATOR(["管理者"])

  CC -- "token" --> MCP
  CD -- "token" --> MCP
  CU -- "token" --> MCP
  MCP -- "検証・利用ログ記録" --> D1
  MCP -- "本文読込" --> SKILLS
  OPERATOR -- "ADMIN_TOKEN" --> ADMIN
  ADMIN -- "発行・失効・一覧" --> D1

未許可のスキルは MCP ツールとして登録されないため、 tools/list にすら現れません。実行時の権限チェック漏れが構造的に起きない設計です。

利用の流れ

接続してから実際にスキルが使われるまでの一連の流れです。

sequenceDiagram
  actor U as 利用者
  participant C as クライアント
  participant W as Worker (/mcp)
  participant D as D1

  U->>C: 「マーケの壁打ちして」
  C->>W: tools/list（Bearer token）
  W->>D: トークン検証
  D-->>W: 有効・許可スキル一覧
  W-->>C: 許可されたツールのみ返す
  C->>W: tools/call skill_marketing_sparring
  W-->>C: スキル本文（プロンプト）
  W->>D: 利用ログを非同期で記録
  C-->>U: スキルに沿って壁打ち開始

トークンのライフサイクル

stateDiagram-v2
  [*] --> active: 管理者が発行
  active --> revoked: 管理者が失効
  active --> expired: 有効期限切れ
  revoked --> [*]
  expired --> [*]

クライアント接続手順

管理者から接続URLを受け取ったら、使っているクライアントに応じて登録します。

Claude Code

claude mcp add --transport http skill-mcp "https://<worker-url>/mcp" \
  --header "Authorization: Bearer <あなたのトークン>"

登録後 /mcp コマンドで connected になっていれば成功です。

Cursor

~/.cursor/mcp.json（全プロジェクト共通）または .cursor/mcp.json（プロジェクト単位）に追記します。

{
  "mcpServers": {
    "skill-mcp": {
      "url": "https://<worker-url>/mcp",
      "headers": {
        "Authorization": "Bearer <あなたのトークン>"
      }
    }
  }
}

Claude（claude.ai / Claude Desktop）

「カスタムコネクタ」機能（Settings もしくは Customize → Connectors → Add custom connector）で登録します。 ヘッダー認証は現状ベータのため、接続URLにトークンを直接含めた形をそのまま貼るのが確実です。 

https://<worker-url>/mcp?token=<あなたのトークン>

接続後の使い方

登録が終われば、あとは普通に話しかけるだけです。

「マーケの壁打ちして、この訴求文言どう思う？」

と言えば、対応するスキルのツールが自動的に選ばれ、スキル本文が適用されます。 何が使えるか分からないときは「使えるスキル一覧を見せて」と言えば一覧が返ります。

セキュリティ設計

項目設計
トークン 256bit乱数。サーバーには SHA-256 ハッシュのみ保存し、平文は保存しない。発行時に一度だけ表示される。
権限制御 許可されていないスキルはツールとして登録されないため、一覧にも実行にも現れない。
失効 管理APIから即時失効可能。以後そのトークンでの接続は全て拒否される。
管理用認証情報 受講生用トークンとは別名前空間（ADMIN_TOKEN）で保護。値自体をどこにも保存せず、 パスフレーズから毎回同じ値を計算で導出する運用も可能。
監査 誰が・いつ・どのスキルを呼んだかを利用ログに記録。異常があれば即座に該当トークンを失効できる。

運用

スキル本文はサーバー側の1ファイルとして管理しており、内容を更新して再デプロイするだけで 次回呼び出しから全利用者に反映されます。個別のクライアント側の再設定は不要です。

トークンの発行・一覧・失効は管理API経由でコマンド一つで行えます。利用状況もいつでも確認できます。
